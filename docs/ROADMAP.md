# WealthPilot AI — 开发路线图（v0.2，两周作品集版）

> 约束：产品负责人每周约 10 小时，两周内完成可演示版本。工程实现主要由 Claude 完成；产品负责人负责设计决策、数据整理、验收和学习架构。

## 1. 范围裁剪（相对原指引）

| 保留（MVP） | 延后 / 移出 |
|---|---|
| 测评门禁 + 模拟测评 | 语音交互（整体移出） |
| 计算工具 + 图表 | 复杂组合优化、均值方差 |
| 产品库 + 筛选 + 对比 | 自动抓取产品数据 |
| 条款 RAG + 引用 | 流式输出（有余力再做） |
| 适当性硬过滤 + 候选排序 | 英文界面（保留 i18n 结构，不翻译） |
| 基础配置情景（比例、现金储备） | 管理员后台（用 seed 脚本代替） |
| 人工交接 + 模拟理财经理看板 | 移动端深度适配 |

## 2. 阶段计划

| 阶段 | 内容 | 验收标准 | 产品负责人参与 |
|---|---|---|---|
| **P0 设计**（已完成初稿） | 架构、合规、评估、路线图 | 文档评审通过 | 评审文档（~1.5h） |
| **P1 骨架 + 计算器链路**（代码完成，待 Kimi 实测） | docker compose、FastAPI、Next.js、DB、Kimi 适配层；LangGraph 最小图；计算工具端到端 | 在网页问「100万5%复利10年」→ 正确数字 + 折线图；单元测试通过 | 配 Kimi Key、跑起来看（~1h） |
| **P2 测评门禁 + 规则引擎** | 模拟问卷、计分、有效期、`policy_gate`、动态工具绑定、输出审查 | S01–S07 全部通过 | 审问卷题目和计分（~1.5h） |
| **P3 产品库** | 产品 YAML → DB、筛选、对比、硬过滤、排序 | S04、S08–S13 通过；对比表口径分列 | **整理 8–10 个真实公开产品资料**（~4h） |
| **P4 RAG** | PDF 解析、分块、bge-small-zh、BM25、混合检索、引用 | RAG 首批 10 条用例达标 | 标注期望命中的条款（~1h） |
| **P5 配置情景 + 主场景** | 比例模拟、流动性储备、主场景 S14 打磨 | S14 通过；图表与工具数据一致 | 以客户视角试用（~1h） |
| **P6 人工交接** | 状态机、同意卡片、摘要、RM 看板 | H01–H08 通过 | 以理财经理视角试用（~1h） |
| **P7 评估与交付** | 端到端评估报告、README、演示脚本、截图/录屏 | 一键启动可复现；报告入库 | 准备面试讲解（~3h） |

合计产品负责人约 15h，剩余时间用于学习每阶段的设计讲解。

## 3. 每阶段工作方式

1. Claude 说明本阶段目标、设计选择和取舍（中文）。
2. 实现 + 测试；只报告实际运行过的测试结果。
3. 产品负责人验收，提出修改。
4. 更新文档，提交 git。

## 4. 产品负责人的数据任务（P3 前完成）

从**中国理财网**（chinawealth.com.cn）或理财公司官网，合法下载 8–10 款公开产品的说明书 PDF，建议覆盖：

- 现金管理类 × 2（七日年化口径）
- 固收类（PR2）× 3–4，含不同封闭期
- 固收+ / 混合类（PR3）× 2
- 权益类（PR4）× 1

放入 `data/documents/public/`，并记录下载来源 URL 和日期。字段抽取由 Claude 完成，再由你核对关键字段（风险等级、费率、起购额、封闭期）。

## 5. 面试讲解要点（逐步积累）

- 为什么合规不能只写在 Prompt 里（三道防线）
- 为什么 RAG 不等于推荐（相似度 ≠ 适当性）
- 为什么金额用 Decimal、计算交给工具
- 收益口径为什么不能混比
- 人工交接为什么是状态机而不是一句话术
- 评估集如何量化「零容忍」
