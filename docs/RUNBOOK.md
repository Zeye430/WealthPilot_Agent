# WealthPilot AI — 故障处理手册（Runbook，v0.1）

> 给值班人员用：看到告警或收到投诉时，按「现象 → 判断 → 处理 → 事后」逐步排查。
> 所有判断都基于系统已有的工具：运维看板 `/ops`、就绪检查 `/health/ready`、带请求编号的 JSON 日志、`turn_metrics`（每轮指标）、`policy_decisions`（审查决策）、`tool_calls`（工具调用）。
> 告警阈值见 [ARCHITECTURE §4.8](ARCHITECTURE.md)；各类故障对客户的表现见 [ARCHITECTURE §4.7](ARCHITECTURE.md)。

## 0. 通用工具

**按请求编号追查一轮对话**（客户反馈时让其提供，或从看板「最近 50 轮」复制）：

```bash
# 日志（JSON 格式时）
grep '"request_id": "<编号>"' app.log
```

```sql
-- 这一轮的运行指标：结果、审查结论、命中规则、耗时、模型调用与工具
SELECT * FROM turn_metrics WHERE request_id = '<编号>';
-- 同一会话的审查决策与工具调用（需要审计权限；含规则命中的片段）
SELECT checkpoint, decision, reason_codes, rule_version, created_at
  FROM policy_decisions WHERE conversation_id = '<会话编号>' ORDER BY created_at;
SELECT tool_name, status, input, created_at
  FROM tool_calls WHERE conversation_id = '<会话编号>' ORDER BY created_at;
```

**依赖状态**：`curl -s https://<域名>/health/ready | jq`（数据库、模型配置、熔断、知识库索引、语音模型；必需项不可用时返回 503）。

**原则**：先止损（让客户能用、不说错话），再定位，最后复盘。涉及合规的问题（错误推荐、承诺收益）同时通知合规负责人。

## 1. 模型熔断打开

- **现象**：看板「模型熔断」显示「已熔断」；异常率上升；客户看到「AI 助手暂时繁忙」。
- **判断**：
  1. 看板最近 50 轮中，结果为「异常」的轮次的 `llm_errors`：模型调用是否持续失败；
  2. 日志中 `agent failed` 的异常类型：`APITimeoutError`（超时）、`RateLimitError`（限流）、`AuthenticationError`（密钥失效）、`APIConnectionError`（网络）；
  3. 查看模型服务商状态页。
- **处理**：
  - 服务商故障：熔断会每 30 秒放行一个探测请求，恢复后自动关闭，无需操作；超过 15 分钟仍未恢复，评估切换备用模型（见 §9）。
  - 被限流：检查是否有异常流量（看板对话量），必要时临时降低每用户限流（`RATE_LIMIT_CHAT_PER_MINUTE`），或向服务商申请提高额度。
  - 密钥失效：轮换密钥（见 §10）。
- **事后**：记录故障时长与影响轮次（`turn_metrics` 中 `outcome IN ('ERROR','BREAKER_OPEN')`）。

## 2. 兜底率上升

- **现象**：兜底率超过 5%（客户看到「这个问题我暂时无法给出合适的回答」）。
- **判断**：看板「合规规则命中」中哪条规则在上升，按规则代码抽查：

  ```sql
  SELECT request_id, violation_codes, created_at FROM turn_metrics
   WHERE outcome = 'FALLBACK' AND created_at > now() - interval '1 hour';
  ```

  再按会话编号查 `policy_decisions`，看改写前后命中的片段，区分两种情况：
  1. **模型确实写了违规内容**（如承诺收益）：规则在正常工作，问题在模型或提示词；
  2. **规则误拦**（合规的表述被拦，如否定句、引用的警示语）：规则需要校准。
- **处理**：
  - 模型变差（常见于服务商更新模型）：固定模型版本或回退；跑一次场景评估确认（`run_scenarios.py --repeat 3`，中英文各一次）。
  - 规则误拦：**不要直接删规则**。补充误拦样例为单元测试 → 修正规则 → 跑完整场景评估 → 合规负责人确认 → 发布。紧急时可回滚到上一个规则版本（规则随代码版本发布）。
- **事后**：误拦样例与修复写入 `docs/COMPLIANCE_DESIGN.md` 与评估用例。

## 3. 客户投诉「AI 说错了」

- **判断**：按请求编号调出这一轮（§0），对照：回答引用的产品要素、收益数字、金额是否与工具结果一致；审查是否命中规则、是否改写过。
- **处理**：
  - 回答有误但审查未拦截：属于规则漏拦。补测试与规则（同 §2），评估该问题是否影响其他客户（按相似问法检索近期对话）。
  - 涉及错误推荐或承诺收益：通知合规负责人；由理财经理联系客户澄清。
- **事后**：纳入场景评估集，防止回归。

## 4. P95 延迟升高

- **现象**：P95 超过 20 秒；客户等待时间长，可能出现「处理时间较长」的超时回复。
- **判断**：对比「模型调用耗时」与「整轮耗时」（`turn_metrics.llm_ms` 与 `latency_ms`）：
  - 模型耗时占大头：上游变慢（服务商负载、提示词变长导致输入 token 增加）；
  - 整轮远大于模型耗时：系统排队（线程或数据库连接不足，见 §5）。
- **处理**：上游变慢时确认是否接近单轮 60 秒上限（超时轮次 `outcome = 'TIMEOUT'`）；系统排队时扩容实例。
- **事后**：若输入 token 持续增长，检查历史长度与工具结果大小（见 [COST_ESTIMATE §3](COST_ESTIMATE.md)）。

## 5. 「系统繁忙」（503）/ 数据库连接池耗尽

- **现象**：客户看到「系统繁忙，请稍后再试」；日志中有 `database pool exhausted`。
- **判断**：看板对话量是否突增；数据库连接数（`SELECT count(*) FROM pg_stat_activity`）是否接近上限。
- **处理**：
  - 流量突增：扩容后端实例（每实例最多 10 + 20 个连接，保证「实例数 × 30」小于 PostgreSQL 连接上限）；
  - 流量正常但连接耗尽：检查是否有慢查询或未释放的连接（`pg_stat_activity` 中长时间 `idle in transaction`）。
- **事后**：根据峰值调整 `DB_POOL_SIZE` / `DB_MAX_OVERFLOW` 与实例数；参考压测报告 `evaluations/reports/load-*.md`。

## 6. 数据库不可用

- **现象**：`/health/ready` 返回 503，`database.ok = false`；部署平台停止向实例转发流量；客户无法使用。
- **处理**：按数据库运维流程切换到备库；恢复后确认迁移版本一致（`alembic current`）。存活检查 `/health` 不依赖数据库，容器不会因此被反复重启。
- **事后**：核对故障期间是否有写入丢失（对话、交接状态）。

## 7. 工具失败率上升

- **现象**：看板「工具调用」中某个工具失败数上升；客户回答中出现「这部分暂时查不到」。
- **判断**：日志中 `tool failed`（带请求编号与异常类型）。常见：`search_documents` 失败（知识库索引不可用或为空，看就绪检查 `knowledge_index`）。
- **处理**：知识库索引为空时重建：`uv run python ../scripts/build_index.py`；其他工具按异常定位。工具失败不会让整轮对话失败（P8-4 已隔离），但会影响回答质量，应尽快恢复。

## 8. 合规规则需要紧急变更

例如监管发布新的禁用表述、或发现某条规则大面积误拦。

1. 合规负责人书面确认变更内容；
2. 修改 `backend/app/compliance/output_guard.py`，补充违规样例与合规样例的单元测试；
3. 运行全部测试与中英文场景评估（`--repeat 3`），结果附在变更记录中；
4. 更新 `docs/COMPLIANCE_DESIGN.md`；
5. 发布后观察看板中该规则的命中次数与兜底率 24 小时。

规则带版本号（`RULE_VERSION`），每条审查决策都记录当时的规则版本，事后可追溯「当时按哪个版本判断」。

## 9. 切换模型

1. 在测试环境修改 `LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`；
2. 跑中英文场景评估各 3 次，与当前模型对比通过率、兜底率、改写次数、延迟与每轮费用；
3. 达标后经合规确认再切换生产；同步更新费用单价（`LLM_PRICE_*`）；
4. 切换后 24 小时重点观察兜底率与规则命中分布。

## 10. 密钥轮换

| 密钥 | 位置 | 轮换步骤 | 影响 |
|---|---|---|---|
| 模型 API 密钥 | `LLM_API_KEY` | 服务商生成新密钥 → 更新配置 → 滚动重启 → 吊销旧密钥 | 无（滚动重启） |
| 手机银行凭证密钥 | `APP_TICKET_SECRET`（生产中为银行公钥） | 与银行约定生效时间；过渡期可同时接受新旧两把（需代码支持多密钥） | 凭证有效期仅 60 秒，影响很小 |
| 指标令牌 | `METRICS_TOKEN` | 更新配置与 Prometheus 抓取配置 | 抓取短暂失败 |
| 数据库密码 | `DATABASE_URL` | 按数据库运维流程 | 滚动重启 |

## 11. 客户数据请求

- **查询本人数据**：客户的对话、本次需求、测评记录、提醒均按客户编号存储，可导出。
- **删除**：演示环境「我的 → 清空演示数据」会删除该客户的全部对话、需求、测评、交接与提醒；生产中需与监管要求的保存期限协调（审计记录可能需要保留），由合规确认后执行。
- 运行指标 `turn_metrics` 不含客户编号与对话内容，不在删除范围内。
